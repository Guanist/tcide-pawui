# UX 路线图：吸收 Codex / DeepSeek Harness / Trae 的长处

来源：对三个产品的独立调研（2026-10）
- **Codex 客户端**（CLI + IDE 扩展 + app/cloud）—— 官方文档，部分经镜像核对（官方站对抓取返回 403）
- **DeepSeek Harness V0.2.0-rc.2** —— 直接读本机安装包内 ~60 个包的 README 与注册代码（最硬的证据）
- **Trae IDE v3.3.99** —— 官方文档与发布说明（注意：Builder 已是历史形态，SOLO 的"仅 Max 模型"说法已过时）

**怎么读这张表**：`命中` 列是"三家里有几家做了这件事"。**三家都做的**，说明它不是某家的偏好，而是这类产品的通用答案 —— 优先做。

## 第三梯队：单家但值得偷

- **附件轨道 + 整页拖放**（DSH）—— 图文混排、上传中/失败/重试状态清晰
- **轮次大纲按需翻页**（DSH）—— 超长会话跳转而不必整段载入
- **聊天滚动：语义锚点 + 意图跟随**（DSH）—— 历史前插不跳、流式时不抢滚动
- **设置分页 + staged 表单**（DSH）—— 离开不误存、冲突不丢草稿
- **后台作业面板**（DSH）—— 长命令可观察、可终止
- **浏览器预览闭环**（Trae）—— 选元素→改样式→看效果（工作量大）
- **中文场景优化**（Trae）—— 界面与规则模板全中文（我们本来就是中文，已具备）
- **Figma 设计还原**（Trae）—— 需外部授权，暂不做

## 本项目的执行顺序（建议）

### 已完成（本轮）
- ✅ **运行中可见性（第一刀）**：状态栏 Spinner + `busy` 状态；
  顺带修掉一个真 bug —— `cmd_run_tests` 原先是**同步**执行（超时 300 秒），
  跑测试时窗口整个卡死；现在走后台线程 + `_run_async` 统一封装。

### 下一步（按"三家都命中"的优先级）
1. **权限三档**（第一梯队 #1）—— 把现在的二元"审查门"升级为
   `只读 / 逐次确认 / 自动`，选择器放设置面板 + 状态栏常显当前档位
2. **每轮变更卡 + diff 审查**（#2）—— 对话里出现"本轮改了 N 个文件 +X −Y"的卡片，
   点击展开逐文件 diff；复用已有的 `diff_modal`
3. **计划模式**（#3）—— `/plan` 先出方案、落盘 `.tcide/plans/`、人批了再执行
4. **运行中可见性**（#4）续 —— 面板自动跟随（写代码切编辑器、跑命令切终端）+ 轨迹视图

### 之后
5. 上下文引用 `@文件`（#6）· 6. 工具调用分区渲染（#9）· 7. 快捷键注册表（#8）
8. 会话/消息回退（#5 的界面部分）· 9. 规则文件 `AGENTS.md` 兼容（#10）

### 明确不做（以及为什么）
- **SOLO 式任务主视图重构**：把工作区换成"任务面板为主"是产品级改版，
  与本项目"IDE 为主"的定位冲突，收益不确定
- **Figma 还原**：依赖外部授权与设计文件接口
- **云端 best-of-N**：需要服务端，本项目坚持本地优先
